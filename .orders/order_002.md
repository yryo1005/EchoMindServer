# Order 002

## ユーザーからの指示（原文）

まずは話者分離や会話抽出，音声認識，ベクトル検索精度のベンチマークをしてモデルを選定した方が良いのでは

## 指示の解釈

Order 001で提示したサーバー実装計画について，実装着手前に，仕様書に挙げられている各要素技術（VAD・会話区間抽出，話者分離，音声認識，文章埋め込みによるベクトル検索）の精度をベンチマークし，使用するモデル・手法を選定すべきとの指示である．

これは `@.ai/ai-dev-kit/machine_learning.md` が想定する「学習（train/validation split，エポック学習）」とは異なり，既存の事前学習済みモデルを対象とした**推論精度の比較評価**である．そのため，`train.py`の学習ループやResultLoggerクラスはそのままは適用できないが，以下の点は引き続き遵守する．
- `programs/ex{n:03}_{共通条件}/{比較手法}/` の実験ディレクトリ構造
- `outputs/ex{n:03}_{共通条件}/{比較手法}/.../metrics.json` への評価結果保存
- 可視化ノートブック（`visualize_result.ipynb` 相当）による比較結果の提示
- `.reports/report_{n:03}.md` での結果まとめ

ベンチマークの結果，仕様書記載のモデル（pyannote, Haas-ja, ruri）が妥当であればそのまま採用し，精度・速度上の問題が確認された場合は代替モデルの採用をユーザーに提案する．

ベンチマークに先立ち，調査の結果，日本語かつ複数話者・話者分離済みの無料公開コーパスは見当たらなかった．そのため，JSUTやCommon Voice（日本語）等の単一話者コーパスから正解ラベル（発話区間・話者・テキスト）が既知の音声を人工的に結合・混合し，疑似的な複数話者会話データを作成してベンチマークに用いる方針とする．この点は実装ステップの提案時にユーザーへ明示する．
