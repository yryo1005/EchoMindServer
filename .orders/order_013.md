# Order 013

## ユーザーからの指示（原文）

1. サーバーが処理中に止まると、状態が processing のまま変わらない（重要）
2. 「古くなった」かどうかを created_at で判定している
(詳細はレビュー指摘の全文を参照)

これらを修正してください

## 指示の解釈

Order 012で追加した処理状況ポーリングAPI(`GET /api/upload/{id}/status`)について，外部レビューで指摘された2件の不具合を修正する．

1. **状態確認APIが停滞を検出しない**: 停滞判定(`_is_retryable`相当)は`POST /api/upload`での再送時にしか適用されておらず，`GET /api/upload/{id}/status`は常に生のステータスをそのまま返していた．サーバーが異常終了した場合，クライアントはポーリングを続けるだけで"processing"から変化せず，再送するきっかけを得られない．→ 状態確認APIでも同じ停滞判定を適用し，検出した時点でDB上のステータスを"failed"へ更新してから返すようにする．

2. **停滞判定の基準が`created_at`**: `created_at`(最初のアップロード時刻)は再試行時に更新されないため，最初のアップロードから30分以上経過した後に正常に再試行している最中に，別の並行アップロードがその記録を「停滞している」と誤判定し，二重に処理してしまう可能性があった．→ `UploadRecord`に`processing_started_at`(処理を開始するたびに更新される専用の列)を追加し，これを停滞判定の基準とする．

既存の`upload_records`テーブルへの列追加のため，`scripts/migrate_add_processing_started_at.py`を作成した．
