# Order 005

## ユーザーからの指示（原文）

十分な制度であると判断できるのであればサーバー実装に進んでください

## 指示の解釈

Order 004で実施したex002_model_benchmark(比較対象モデルの追加，テストデータの拡充)の結果をもって，モデル選定の精度・信ぴょう性が十分かどうかをAIエディタ自身が判断し，十分であればサーバー本体(`programs/server/`)の実装に進むよう指示している．

## 判断

`.reports/report_002.md`の結果を踏まえ，以下の理由からサーバー実装に進むことを決定する．

- 各タスクにおいて，仕様書記載のモデル(Haas-ja-v1.0, ruri-large-v2, pyannote/speaker-diarization-3.1)は，比較対象に対して明確に劣っている箇所がなく，上位グループに位置している．
- 上位モデル間の差は評価データのばらつき(標準偏差)より小さく，これ以上サンプル数や比較対象を増やしても「断定的な最良モデル」が確定する見込みは低い．一方で，仕様書記載のモデルを採用することの妥当性は十分に確認できた．
- 2回のベンチマーク(ex001: 30件の疑似会話，ex002: 80件・重複発話・ノイズ付加)を通じて，モデルの相対的な優劣の傾向(Haas-ja/reazonspeechが上位，ruri系が上位，pyannote 3.1とcommunity-1に大差なし)は一貫していた．

## 最終的なモデル選定

- **音声区間抽出(VAD)**: Silero VAD(依存ライブラリが軽量で，pyannote segmentation-3.0と同等の精度)
- **話者分離**: `pyannote/speaker-diarization-3.1`(仕様書記載)
- **音声認識**: `Haas-ja-v1.0`(仕様書記載．専門用語用のカスタム辞書機能`haas_asr.Vocabulary`を使用)
- **文章ベクトル化**: `cl-nagoya/ruri-large-v2`(仕様書記載)
- **回答生成**: Gemini API(仕様書記載)
- **データベース**: PostgreSQL + pgvector(ユーザー回答済み)

以上のモデル選定に基づき，`programs/server/`にFastAPIサーバーを実装する．
